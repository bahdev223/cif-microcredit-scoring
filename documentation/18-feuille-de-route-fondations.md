# Feuille de route des fondations

## Règle de priorité

Le dépôt ne doit plus privilégier des écrans de gestion opérationnelle de crédit ou de paiement. La priorité est la fondation de données du scoring. Toute évolution doit servir l'acquisition, la compréhension, la qualification, l'historisation, la transformation, l'apprentissage, la validation, l'explication, la décision humaine ou le suivi.

## 1. Scoring Data Foundation

1. Schéma canonique V1 ;
2. dictionnaire et gouvernance des données ;
3. import CSV souple ;
4. import XLSX ;
5. mapping dynamique et connecteurs versionnés ;
6. provenance et lineage ;
7. Data Quality en six dimensions ;
8. Data Mart ;
9. snapshots de demande à T0 ;
10. snapshots de performance ;
11. définition versionnée BAD/GOOD ;
12. Dataset Builder.

## 2. Analysis Foundation

13. cadres d'analyse par activité et produit ;
14. rubriques dynamiques et contrat de collecte ;
15. calculs métier versionnés ;
16. Feature Engine séparant variables canoniques et métier.

## 3. Model Foundation

17. Model Lab ;
18. validation hors échantillon et temporelle ;
19. Model Registry ;
20. Scoring Engine ;
21. monitoring, recalibration et validation humaine des nouvelles versions.

## Positionnement de la démo

Fatou représente le commerce : historique importé + situation actuelle + instruction humaine. Bakary représente l'agriculture saisonnière : le même système, mais un cadre de collecte et une lecture des flux différents. Ces cas rendent visible pourquoi un formulaire universel de revenu mensuel ne suffit pas.

## À ne pas faire maintenant

Ne pas construire de caisse, d'encaissement, de décaissement réel, de comptabilité, de CRM, de connecteurs spécifiques non observés sur le terrain, ni de modèle statistique prétendument robuste à partir des seuls petits jeux synthétiques.
